### 三条路径

| 路径 | 适合谁 | 成本/风险 |
|---|---|---|
| **A. 原地观望（推荐）**：留在 3.1.4，在独立文件夹试装 3.1.6 玩一两周，没问题再迁 | 不想当小白鼠、依赖二改的你 | 最低；试玩不影响现有环境 |
| **B. 直接升 3.1.6**：按第 3 节迁移二改 | 用得上骰子/管理员等新功能、愿意跟进 | 中；官方称 3.1.5 修复了渲染协作，但场外有用户反馈更新后有其他 bug |
| **C. 回 3.1.0**：把二改移植到 3.1.0 | 完全用不到 3.1.1–3.1.4 的新功能（scene-planner 等） | **最高**：二改锚点 scene-plan-tool.js / scene-planner-presets.js 在 3.1.0 不存在，无法直接移植，需重写；且 3.1.0 仍偶发同一渲染 bug |

### 为什么社区「回 3.1.0」的潮流不适用于你

- 据反馈，部分用户更新 3.1.5/3.1.6 后遇到其他 bug 而回退；但他们多为**无修改原版用户**，回退零成本。
- 你的二改已深度绑定 3.1.4 结构（36 个文件 +1 新增），回退等于重写二改。
- GitHub issues 全库仅 8 条（场外反馈无法在此核实）；其中 2026-09-19 的提交确认修复了你的渲染问题：

  > fix(draw): 整条重写楼层 DOM 后通知其它渲染扩展（**修复插图后酒馆助手的 html 代码块退回源码**）

### 版本与修复事实

- 官方在 v3.1.5 修复了你追了一整天的 bug（v3.1.5 更新日志「画图」：「修复追加生图覆盖已有图片、图片位置变化及**与其他消息渲染器的协作问题**」）；机制=图片局部 DOM patch 冲掉了把 HTML 代码块渲染成页面的其它渲染器（酒馆助手等）成果。

## 3. 回家后执行：迁移到 v3.1.6

### 3.0 先备份（必做）

- 复制整个 `LittleWhiteBox_折疊標題` 文件夹到安全位置（U盘/云盘）
- 备份 SillyTavern 的 `chats/` 和设置
- ⚠️ v3.1.5 有破坏性变更：经济系统改为全局账户，**旧聊天的余额/流水/存款/库存等经济记录不迁入、加载旧聊天时会清理**（学习记录与人物属性保留）。知情后再升。

### 3.1 安装 git（若没有）

```bash
xcode-select --install      # macOS
git --version               # 验证
```

### 3.2 推荐路线：git 三件套（最安全、可追溯）

```bash
mkdir -p ~/lwb && cd ~/lwb

# 1) 克隆官方完整历史
git clone https://github.com/RT15548/LittleWhiteBox.git official
cd official

# 2) 先在官方 v3.1.6 上建工作分支
git checkout v3.1.6
git checkout -b my-mod-316

# 3) 把你的二改目录复制进来（只复制内容，排除下面这些）
#    假设二改目录在 ~/lwb/my-current
rsync -a --exclude=.git --exclude=node_modules --exclude=.DS_Store \
  --exclude=LittleWhiteBox --exclude=LittleWhiteBox3.1.0 --exclude=info \
  ~/lwb/my-current/ ./

# 4) 先不要 commit，直接看与官方 3.1.6 的差异（这就是「要在新版上重做的二改」）
git diff --stat
```

由于官方 3.1.5/3.1.6 也动过这些文件，**直接覆盖会把官方修复盖掉**（尤其 iframe 渲染协作修复）。所以接下来逐文件处理：

```bash
# 对每个有差异的文件，用三方对比，只挑出「你的新增」，保留官方新代码
git diff <文件>          # 看差异
# VS Code 用户：直接在编辑器里对冲突块逐块取舍（Accept Current/Incoming/Both）
```

取舍原则：
- **渲染相关**（scene-placement.js 的补空行、三家 provider 的 processMessageById 补触发）→ **先不要移植**，3.1.5 官方已修，升级后先验证，没复现就不需要。
- **v15 进阶预设**（scene-rules-pro.md + scene-planner-presets.js + migration + draw-settings 白名单 + novel-prompts）→ 需要移植，但 3.1.5「更新场景分析与绘图预设」可能改了预设结构，移植后跑一次生成验证。
- **标题句式**（scene-plan-tool.js）→ 官方版该文件已变，把新的标题描述文案移植到新版对应字段即可。
- **图标/外观**（draw-common.js 的 RELOAD_ICON_SVG、失败卡 CSS、去虚线边框）→ 3.1.6 官方新增了「图片卡片编辑提示词并重绘」，按钮结构有变化，按新版结构重新挂图标和样式，别整文件覆盖。
- **早期小二改**（gallery-cache / message-preview / story-outline / pending-image-jobs 等各 1–5 行）→ 看 diff 内容，确认新版没有同等功能后再补。
- **测试文件** → 可全部不移植，或源码移植完成后再对应更新。

全部取舍完：

```bash
git add -A
git commit -m "my-mod: 基于官方 v3.1.6 的二改（进阶预设/标题/图标外观）"
```

### 3.3 备选路线：不用命令行

1. 从 https://github.com/RT15548/LittleWhiteBox/releases/tag/v3.1.6 下载官方包，解压成新扩展目录。
2. 用 VS Code 打开两个文件夹，右键其中一个 → **Compare Folders**（或装 Compare Folders 扩展；Windows 可用 WinMerge，Mac 可用 Beyond Compare / meld）。
3. 逐文件按上面的「取舍原则」把二改搬进新版。
4. 搬完在 SillyTavern 里实测一轮带图 + 带分支选择器 HTML 的生成。

### 3.4 后端插件（如使用后台离生线图）

v3.1.5/3.1.6 的 server-plugin 有更新，需重新部署：

1. 将新版 `server-plugin/littlewhitebox-image-jobs` 复制到 `SillyTavern/plugins/littlewhitebox-image-jobs/`
2. 确认 `config.yaml` 中 `enableServerPlugins: true`
3. 重启 SillyTavern（要求 Node.js 18+）
